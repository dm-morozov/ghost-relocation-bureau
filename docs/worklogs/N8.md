# N8 · доступность и адаптивность

## Проблема

После параллельной интеграции необходим сквозной проход пяти разделов на 320/390/desktop в дневной, ночной и системной теме: клавиатура, фокус, контраст и reduced-motion. Прежние локальные проверки нескольких элементов не подтверждают доступность всего приложения.

## Решение и реализация

По поручению автора подготовлена отдельная QA-матрица без изменения кода приложения. Прочитаны `docs/parallel-delivery.md`, `docs/audit-2026-10-18.md` и текущие компоненты/стили. Материалы: `artifacts/accessibility-qa/README.md` (сценарии и восемь предварительных findings), `matrix.csv` (45 комбинаций), `computed-contrast.js` (read-only сбор computed styles без новых пакетов).

Продуктовый объём и границы владения задал автор; AI составил сценарии, изучил исходники и подготовил измеритель. Публичный Worklog остаётся в ведении W.

## Подготовительные проверки

Подготовительный этап завершён. Синтаксис измерителя проверен Node; 10 синтетических проверок подтвердили пары 21:1/1:1, alpha-смешивание, пороги размера текста и отдельные статусы opacity/gradient/disabled (`helper-validation.json`). Это проверка измерителя, а не браузерные измерения приложения. Матрица проверена на 45 уникальных сочетаний. Хэши восьми исходников на момент подготовки сохранены в `preparation-source-hashes.json` для последующей сверки.

По коду выделены риски фокуса после удаления последней заявки/закрытия прогноза игры, мобильной прокрутки отчёта, фокуса заголовков, состояний темы и границ адаптивной компоновки. Это был предварительный этап, без браузерных измерений.

## Итог браузерного прохода после сигнала интеграции

Использован computer-use skill и отдельный Chrome origin `http://127.0.0.1:5289/` со своими демоданными. Все 45 базовых комбинаций открыты и измерены; сохранены JSON computed styles и PNG. В базовых состояниях страницы overflow отсутствует. Всего 7594 текстовых наблюдения: 6918 измеренных плоских пар и 676 с оговорками для ручной проверки; рассчитанных пар ниже порога не найдено. Это не полное покрытие всех интерактивных состояний и нетекстового контраста.

Подтверждены клавиатурные сценарии story details, mobile request/back, создание подходящего дома и назначение с возвратом, новая форма/закрытие, стрелки темы, focus/ArrowRight именованной прокрутки отчёта, прогноз/назад/advance/restart-cancel игры. Ночной отчёт следует выбранной теме.

Выявлены P2 (после закрытия предпросмотра фокус уходил в body) и P3 (игровой прогноз на 320 расширял страницу на 1px). Исправления внёс основной чат. После reload собственный браузерный readback подтвердил закрытие обоих: Escape/Cancel/Apply на desktop/320 light вернули видимую кнопку подбора, дополнительно прошёл Escape 320 dark; открытый прогноз 320 dark имеет scrollWidth=clientWidth=305. Исходники приложения я не редактировал.

Рекомендацию по слабым границам полей основной чат также исправил. Финальный computed readback на 320/390/1440 в light и system→light: border `#738578`, контраст поиска/select 3.888:1 к фону поля и 3.883:1 к соседней карточке (ранее 1.349:1). Dark сохранил свою границу и 3.267:1 / 3.736:1 соответственно. Проверены text/number/date inputs новой заявки; textarea отдельно не отрисован и не измерен. Для проверенных контролов рекомендация закрыта, новых подтверждённых дефектов не найдено. Подробности и evidence: `artifacts/accessibility-qa/browser-findings.md`.

## Ограничения / следующий этап

Все 45 строк обновлены фактическими результатами и ссылками на evidence. Полный keyboard pass по каждой строке остаётся partial. System фактически разрешается в light; эмуляция system-dark/reduced-motion недоступна advertised browser API и не выполнялась. Normal-анимации измерены; CSS reduce прочитан, но не заменяет runtime проверку. Не проверены 200% browser zoom, все ошибки/hover/нетекстовые индикаторы и удаление последней заявки.

Localhost 5199 не открывался; системные настройки не менялись. Временный viewport override сброшен. Не было commit/push/deploy, изменений приложения или чужих файлов. Полный WCAG-аудит не заявлен. Основная матрица снималась до двух исправлений; именно затронутые сценарии перепроверены отдельно с новым evidence. `browser-source-hashes.json` фиксирует исходники после повторного прохода, не неизменность общей копии на протяжении всего QA.

Папка `artifacts/` исключена существующим `.gitignore` (строка 7); подготовленные материалы доступны локально, но не попадут в commit автоматически. Правила игнорирования и staging не менялись.
