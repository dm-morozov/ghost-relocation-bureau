# N2 · Предпросмотр автоподбора

## Проблема и решение

До этого App показывал итог после записи назначений. По поручению пользователя AI подготовил независимый чистый модуль плана и модальный предпросмотр до применения. Продуктовый выбор: отмена сохраняет текущие назначения и прежний undo; undo создаётся только при подтверждении. Закреплённые вручную и завершённые переезды остаются на своих местах, включая принятые пользователем конфликты, и резервируют вместимость через существующий алгоритм.

## Реализация

- `src/allocation-plan.ts`: `createAllocationPlan`, `allocationSnapshot`, `isAllocationPlanCurrent`, `applyAllocationPlan`. Снимок JSON включает ghosts (включая settledAt), places (включая capacity), assignments, pinned и today. При расхождении apply возвращает null; исходная сессия не мутируется. Отсутствующее pinned совместимо с пустым массивом.
- Строки разделяют добавления, снятия, переезды, сохранённые адреса и заявки без места; выводятся старый/новый адрес, замочки с причиной и конфликты. Итог «Без места» включает снятые назначения.
- `src/AllocationPreview.tsx`: native dialog/showModal, доступное имя и описание, исходный фокус на «Отмена», Escape, восстановление фокуса при размонтировании. Native dialog обеспечивает модальность и ограничение фокуса средствами браузера. Родитель обязан размонтировать компонент после onCancel/onApply.
- `src/allocation-preview.css`: перенос длинных названий, одна колонка адресов и кнопок на 320/390px, максимальная высота с прокруткой, тёмная тема и reduced-motion. Работа с localStorage отсутствует.

## Точный wiring для основного чата

App, алгоритм, общие стили и существующие тесты App в этой задаче не изменялись. Добавить импорты:

```tsx
import AllocationPreview from './AllocationPreview';
import {
  allocationSnapshot,
  createAllocationPlan,
  applyAllocationPlan,
  isAllocationPlanCurrent,
  type AllocationPlan,
} from './allocation-plan';
```

Добавить состояние рядом с allocating:

```tsx
const [allocationPlan, setAllocationPlan] = useState<AllocationPlan | null>(null);
```

Заменить allocate(), сохранив задержку 350мс. Здесь sessionRef — существующий в App JSON текущей сессии:

```tsx
function allocate() {
  if (allocating || allocationPlan || !mayLeave()) return;
  setDirty(false);
  setEditing(false);
  setShowForm(false);
  setShowPlaceForm(false);
  setAllocating(true);
  const source = structuredClone(currentSession);
  const day = todayISO();
  const snapshot = allocationSnapshot(source, day);
  allocationTimer.current = setTimeout(() => {
    allocationTimer.current = null;
    setAllocating(false);
    const latest = JSON.parse(sessionRef.current) as Session;
    if (allocationSnapshot(latest, todayISO()) !== snapshot) {
      setMessage('Данные изменились во время сверки. Запустите подбор повторно.');
      return;
    }
    setAllocationPlan(createAllocationPlan(source, day));
  }, 350);
}

function applyPlan() {
  if (!allocationPlan) return;
  const latest = JSON.parse(sessionRef.current) as Session;
  const next = applyAllocationPlan(allocationPlan, latest, todayISO());
  if (!next) {
    setAllocationPlan(null);
    setMessage('Данные или дата изменились. Запустите подбор повторно.');
    return;
  }
  // Здесь также нужен актуальный guard N1 перед изменением сессии.
  // Если guard отказывает, не выполнять следующие setters.
  setUndo(structuredClone(latest));
  setAssignments(next.assignments);
  setPending(null);
  setTarget(selected ? (next.assignments[selected] ?? '') : '');
  const c = allocationPlan.counts;
  setMessage(
    `Подбор применён. Изменено: ${c.added + c.removed + c.moved}. ` +
      `Сохранено закреплённых и завершённых: ${c.fixed}. ` +
      `Без места: ${c.unassigned + c.removed}. С конфликтами: ${c.conflicts}.`,
  );
  setAllocationPlan(null);
}
```

В конце корневого JSX App:

```tsx
<>
  {allocationPlan && (
    <AllocationPreview
      plan={allocationPlan}
      stale={!isAllocationPlanCurrent(allocationPlan, currentSession, today)}
      onApply={applyPlan}
      onCancel={() => {
        setAllocationPlan(null);
        setMessage('Подбор отменён. Текущие назначения сохранены.');
      }}
    />
  )}
</>
```

`today` в render обновляется существующим интервалом App; проверка в apply использует свежий todayISO(), поэтому переход через полночь защищён даже до следующего тика. Встроенная проверка снимка защищает от изменения состояния этой вкладки; свежесть localStorage другой вкладки обеспечивает N1, а не этот модуль.

## Проверки и результат

### Dialog в интеграционных App tests (уточнение для основного чата)

API модуля и props компонента остаются без изменений. В текущем jsdom `showModal` и `close` отсутствуют: `vi.spyOn(..., 'showModal')` сразу падает, поэтому нужен `Object.defineProperty`. Production fallback намеренно отсутствует: компонент напрямую вызывает native API, ошибки не перехватывает и не скрывает.

Перед монтированием App в каждом соответствующем тестовом файле установить:

```ts
beforeEach(() => {
  Object.defineProperty(HTMLDialogElement.prototype, 'showModal', {
    configurable: true,
    value: function (this: HTMLDialogElement) {
      this.setAttribute('open', '');
    },
  });
  Object.defineProperty(HTMLDialogElement.prototype, 'close', {
    configurable: true,
    value: function (this: HTMLDialogElement) {
      this.removeAttribute('open');
    },
  });
});

afterEach(() => {
  // cleanup должен размонтировать App до удаления методов (effect cleanup вызывает close).
  cleanup();
  Reflect.deleteProperty(HTMLDialogElement.prototype, 'showModal');
  Reflect.deleteProperty(HTMLDialogElement.prototype, 'close');
});
```

Импорты `beforeEach/afterEach` из vitest и `cleanup` из testing-library. При переносе в общий setup и при наличии других dialog mocks сохранить исходные property descriptors и восстановить их после cleanup вместо безусловного удаления. Заглушки только имитируют open для DOM assertions; модальность и фокус вокруг Tab/Shift+Tab проверяются браузером. Готовый рабочий пример находится в `src/AllocationPreview.test.tsx`.

- `npx vitest run src/allocation-plan.test.ts src/AllocationPreview.test.tsx`: 11/11 прошли. Проверены резервирование capacity, сохранение pinned/settledAt, отсутствие мутаций, конфликтующие закрепления, категории изменений, устаревание каждого поля сессии и даты, legacy/пустая сессия, кнопки, keyboard Enter, Escape event, фокус и его возврат.
- `npx tsc --noEmit`: успешно на текущем общем checkout.
- Prettier применён исключительно к пяти файлам этой задачи; `git diff --check` прошёл (только предупреждения Git о CRLF в общих файлах).

## Ограничения и интеграционная приёмка

Интеграцию в App выполняет основной чат. Существующие App tests ожидают применение после 350мс — добавить явный клик «Применить план» в сценариях, где нужны новые назначения; отдельно проверить отмену, сохранение undo, устаревание и N1 guard. Браузерная проверка после подключения остаётся обязательной: реальная Tab/Shift+Tab containment и Escape, 320/390px/desktop, обе темы, 50 длинных имён, reduced-motion и возвращение фокуса. jsdom использует заглушку dialog API и не доказывает реальную модальность или отсутствие переполнения. Публикация, commit/push/deploy не выполнялись.
