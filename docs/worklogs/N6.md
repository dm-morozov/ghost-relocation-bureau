# N6 · Реплики и маленькие истории

## Проблема

В карточках есть портреты и условия переселения, но нет коротких реплик и историй. Один портрет используется разными персонажами; пользователь тоже может выбрать любой портрет. Поэтому назначать биографию по картинке, порядку списка или хешу ID нельзя.

## Решение и реализация

Продуктовое направление пользователя: короткие истории без изменения правил подбора. AI подготовил тексты, явные привязки, изолированный компонент, стили и тесты. Тексты — художественный материал для вымышленных персонажей.

- `src/character-stories.ts`: десять явно пронумерованных текстов по каталогу портретов 0–9; шесть исходных заявок `g1`–`g6` связаны с портретами 0–5, для шести игровых `campaign-0`–`campaign-5` подготовлены отдельные реплики и истории. Портреты 6–9 имеют резервные тексты, но не используются автоматически для пользовательских заявок: исходных имен для них в data/game нет.
- Опознание проверяет ID, полное имя, портрет и набор условий. У исходных demo-заявок отсутствие `portrait` означает исходный портрет согласно `assets.ts`; явная смена портрета, имени или условий включает нейтральный fallback. Порядок условий значения не имеет. Дедлайн и назначенный адрес не входят в историю, чтобы она не обещала состоявшийся переезд.
- Пользовательские заявки получают только «Пожелания к новому адресу указаны в заявке», без выдуманных особенностей и пустого раскрытия. Выбор знакомого портрета или имени не присваивает чужую историю.
- `src/CharacterStory.tsx`: blockquote + нативные details/summary. Имя в summary различает несколько историй на игровом экране. Смена персонажа закрывает раскрытие прежней истории; компонент не перехватывает фокус.
- `src/character-stories.css`: компактный блок, перенос длинного текста, clear для плавающего игрового портрета, светлая/тёмная палитры, видимый focus, без анимации.

## Подключение основным чатом

В `src/App.tsx` и `src/ShiftGame.tsx`:

```tsx
import CharacterStory from './CharacterStory';
```

App: внутри личного дела выбранного ghost, сразу после бейджа состояния и до `request-actions`:

```tsx
<CharacterStory ghost={ghost} />
```

ShiftGame: внутри `currentGhosts(state).map`, в `article.game-ghost`, после абзаца с условиями/температурой и перед label выбора адреса:

```tsx
<CharacterStory ghost={ghost} />
```

CSS импортируется самим компонентом. Не подключать истории в кнопки списка заявок или в select. API принимает существующий Ghost; изменение схемы хранения/data/game не требуется.

## Проверки и наблюдаемый результат

- `npx vitest run src/CharacterStory.test.tsx`: 18/18 passed. Проверены все 12 исходных/игровых персонажей, десять портретных ключей, fallback после изменения идентичности/условий, независимость от порядка условий, отсутствие мутаций, фокус summary через Tab, раскрытие кликом, закрытие при смене персонажа, отсутствие details без истории.
- `npx tsc -b`: passed.
- `npm run build`: passed, включая проверку исходных изображений и 80 WebP. Сам компонент ещё не импортирован в App/ShiftGame, поэтому сборка подтверждает текущее состояние проекта, а его UI отдельно покрыт тестом импорта/рендеринга.
- `git diff --check`: passed; Git вывел только предупреждения о будущей нормализации LF/CRLF в существующих изменённых файлах других потоков.
- Форматирование выполнялось только для четырёх новых файлов N6, без форматирования проекта.

## Результат и ограничения

Готов изолированный модуль N6. App, ShiftGame, data.ts, game.ts и публичный Worklog не редактировались; подключение выполняет основной чат. Проверка реального браузера, обеих тем и ширин 320/390/desktop остаётся после интеграции. jsdom проверяет фокус summary и раскрытие кликом, но не реализует браузерную активацию summary клавишами Enter/Space; её необходимо проверить в браузере. Публикации, commit/push/deploy не было.
