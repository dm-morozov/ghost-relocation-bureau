# F2 — назначения и состоявшиеся переезды

Дата: 2026-10-18. Локальная реализация; без коммита и публикации.

## Изменения и контракт F1

Изменены только `src/report.ts`, новый `src/report-model.test.ts` и этот журнал.
Предыдущие поля `createReport` сохранены, включая `successful`: число назначений
без текущих нарушений. Это поле не обозначает завершённые переезды.

- `assigned`: все заявки с назначением на существующее место, включая конфликтные.
- `settled`: часть `assigned` с непустым `settledAt`.
- `planned`: `assigned - settled`, ожидают переезда.
- `unassigned`: заявки без существующего адреса, включая ссылку на удалённое место.
- `conflicted`: часть `assigned` с текущими нарушениями; может пересекаться с `settled`.
- `requests[].anxiety`: исходная тревожность заявки.
- `attention`: строки со статусом `conflict` или `unassigned`.

Инварианты: `assigned + unassigned = total`, `settled + planned = assigned`,
`successful + conflicted = assigned`. Завершённый переезд с конфликтом учитывается
и среди завершённых, и среди конфликтных. Один `settledAt` без существующего
адреса не увеличивает `settled`; исходная дата остаётся в данных строки.

Правило `attention`: ISO-дедлайн по возрастанию, затем число текущих нарушений
по убыванию, затем тревожность по убыванию, затем уникальный ID заявки
лексикографически по возрастанию. Сравнение ID не зависит от локали окружения.
Порядок исходного `requests` не изменяется. Текст правила экспортирован как
`attentionSortDescription` и включён в Markdown.

Markdown содержит раздельные подписанные счётчики, отдельную колонку даты
завершения и очередь внимания. JSON содержит численные `assigned`, `settled`,
`planned`, `unassigned`, `conflicted`, исходные строки и сортированную очередь.
Прежние формат и версия JSON сохранены; это дополнение существующего отчёта.
Экранирование Markdown включает обратный слеш, разделитель таблицы, HTML-символы
и переносы строк; JSON сохраняет исходный текст.
