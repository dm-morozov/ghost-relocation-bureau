# Тихий адрес — Бюро переселения привидений

Панель оператора сказочного бюро: заявки, подбор адресов с объяснениями, ручные исключения, отчёт и AI Worklog в интерфейсе.

**Приложение:** https://dm-morozov.github.io/ghost-relocation-bureau/

**Репозиторий:** https://github.com/dm-morozov/ghost-relocation-bureau

## Запуск

Нужен Node.js 22.12+ (проверено на 24) и npm. Секреты, аккаунты, база и AI API не нужны.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://127.0.0.1:5173).

```sh
npm test           # автоматические проверки логики
npm run build     # строгая проверка TypeScript и сборка в dist/
npm run preview   # локальный просмотр production-сборки
```

Нажмите «Подобрать места». Из 6 исходных заявок 4 получат места, 2 останутся без адреса. Откройте Эдгара для разбора несовместимых условий и Беллу для просроченного дедлайна.

## Docker

```sh
docker compose up --build -d
```

Откройте http://127.0.0.1:8088. Порт можно изменить переменной окружения `PORT`. Сборка двухэтапная: Node собирает статику, nginx обслуживает её. Остановка: `docker compose down`. Контейнер — дополнительный способ запуска, для GitHub Pages он не нужен.

## Правила и алгоритм

Обязательные условия — жёсткие ограничения. Чердак, отсутствие людей/зеркал проверяются напрямую. Темнота означает свет ≤ 30, тишина — шум ≤ 30, сырость — влажность ≥ 65. Место ограничивает допустимую тревожность. Свет, шум и влажность — шкалы 0–100.

Дедлайн включителен, сравнивается с локальной календарной датой браузера (обновление каждые 30 секунд). Просроченные заявки автоматически не назначаются. Даты демоданных создаются относительно дня загрузки исходного сценария. Сохранённые даты со временем могут просрочиться.

Температура — предпочтение. Формула комфорта:

```text
max(0, 100 − min(60, |желаемая температура − температура места| × 4)
           − round(шум × тревожность / 25))
```

Пример: желаемые 10 °C, фактические 15 °C, шум 20, тревожность 5 → 100 − 20 − 4 = 76. Веса — открытая продуктовая гипотеза для сказочного домена.

Распределение — поток минимальной стоимости: сначала максимум расселённых, затем максимум суммарного комфорта. Обратные рёбра позволяют переназначить гибкую заявку ради заявки с единственным подходящим адресом. Вместимость не превышается. При равенстве используется порядок данных. Дедлайн и тревожность сортируют проблемные заявки в отчёте, но не дают приоритет при распределении.

Ручной выбор показывает нарушения до применения. Конфликтное назначение возможно только через отдельное «Всё равно назначить». В переполненном адресе все жильцы отмечаются как требующие внимания: система не решает за оператора, кто должен переехать. Повторный автоматический подбор заменяет ручные назначения — это указано в интерфейсе.

## Архитектура и ООП

- `src/domain.ts`: модели и независимый от React `RelocationService`.
- `SuitabilityRule`: абстракция правила; `ConditionsRule` и `AnxietyRule` наследуют её и полиморфно реализуют `check`.
- Сервис агрегирует правила через конструктор; закрытое поле `rules` инкапсулирует проверку. Новое правило можно подставить без изменения алгоритма.
- `src/data.ts`: 6 демозаявок и 5 мест.
- `src/storage.ts`: валидация восстановленной сессии.
- `src/App.tsx`: интерфейс и состояние; `src/Worklog.tsx`: открытый журнал AI.

React-компоненты функциональные. Наследование не применяется к UI ради демонстрации ООП. Тестирование алгоритма не требует браузера и сети.

## Хранение и ограничения

До 50 заявок и 50 мест. Во вкладке «Места» нажмите «+ Новое место», заполните параметры и выберите изображение. Новый адрес сразу доступен для ручного выбора; повторный подбор учитывает его автоматически. При создании заявки доступны 10 AI-портретов. Данные хранятся только в localStorage текущего браузера. Старые сессии без справочника мест мигрируют автоматически. Сетевых запросов с заявками, аналитики и контактов нет. Два оператора не разделяют сессию. Кнопки сценариев заменяют заявки и назначения, сохраняя добавленные места. JSON-отчёт скачивается локально.

Повреждённая сессия не ломает запуск: показывается ошибка и загружаются демоданные. При недоступности хранилища интерфейс предупреждает о потере изменений после закрытия. ErrorBoundary перехватывает ошибки рендера. Синхронизация вкладок и серверный аудит не входят в эту версию.

## Проверка перед сдачей

16 автотестов: исходные проверки алгоритма и хранения, миграция справочника, сохранение нового места, недопустимые параметры места, а также два DOM-сценария: создание подходящего адреса для Эдгара с восстановлением после повторного открытия приложения и создание заявки с выбранным десятым портретом.

| Сценарий              | Действия                                                     | Ожидаемый результат                                                              |
| --------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| Базовый подбор        | Исходные данные → Подобрать места                            | 4 назначено, 2 без места, 0 нарушений                                            |
| Нет подходящего места | Эдгар → Проверка всех адресов                                | Для каждого места указаны нарушенные условия                                     |
| Пустой список         | Пустой список                                                | 0 заявок, понятная подсказка, подбор отключён                                    |
| Ручной конфликт       | После подбора: Агата → театр → Применить выбор               | Предупреждение о зеркалах, тревожности и вместимости; назначение ещё не меняется |
| Переполнение          | Подтвердить предыдущий выбор → Отчёт                         | Театр 2/1, жильцы с нарушениями; повторный подбор исправляет переполнение        |
| Восстановление        | Назначить место → перезагрузить                              | Заявки и назначения сохранены                                                    |
| Новая заявка          | Пустой список → Новая заявка → заполнить → добавить → подбор | Заявка появляется и участвует в распределении                                    |
| Поиск                 | Ввести отсутствующее имя                                     | «Ничего не найдено», можно изменить запрос                                       |
| Ошибка хранения       | В DevTools заменить `quiet-address-v1` на `{`, перезагрузить | Понятная ошибка и исходные демоданные                                            |

Проверки первой версии 16.10.2026: 12 тестов, production-сборка и форматирование прошли; Docker-образ собран, контейнер запущен, nginx отвечает HTTP 200 на порту 8088. В браузере проверены подбор, предупреждение и подтверждение конфликта, переполнение в отчёте, пустой список, создание заявки и восстановление после перезагрузки. Проверено продление дедлайна Беллы: результат — 5 назначений из 6. Проверены поиск без результатов и понятная ошибка при имени из пробелов. На фактических ширинах 390 и 320 CSS px проверено отсутствие горизонтального переполнения. На публичном сайте проверены подбор 4/6, встроенный Worklog и скачивание JSON; файл прочитан, данные совпадают со сводкой. Повреждение хранения проверено автоматическим тестом; его ручной сценарий в DevTools ещё не выполнялся.

Обновление с портретами и добавлением мест: 16 автоматических тестов проходят, включая два сценария интерфейса в jsdom. Сборка TypeScript/Vite и форматирование проходят. Все 15 PNG просмотрены отдельно и проверены скриптом: 1254×1254, RGBA, прозрачный фон. Браузерная проверка нового оформления пока не выполнена: управление браузером отключено в Work. ## Публикация

Workflow `Check` проверяет push/PR. `Deploy Pages` публикует main. При первой настройке в Settings → Pages выберите Source: GitHub Actions. Относительный `base` поддерживает подпуть репозитория. Публичная ссылка считается готовой после успешного deployment и браузерной проверки.

## AI Worklog

Отдельная вкладка **AI Worklog**: инструменты, учтённое время (около 20 минут на момент записи первого цикла), распределение работы, суть запросов, решения автора, ошибки AI и улучшения. Код написан AI по запросу автора; ручные правки автора не выдумываются. Дальнейшие изменения и авторское ревью нужно добавить к времени и журналу перед сдачей. Токены не считались: полная статистика недоступна.
