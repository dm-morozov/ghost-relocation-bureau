Законченное локальное веб-приложение по первому заданию MOX: заявки, объяснимый подбор, ручные решения и отдельная короткая игра.

## Запуск

Нужны Node.js >=22.12 и npm. Проверено на Node.js 24.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Для выбора порта: `npm run dev -- --port 5195 --strictPort`. Несколько серверов могут показывать разные версии: сверяйте адрес вкладки с нужным сервером.

```sh
npm test
npm run build
npm run format:check
npm run preview
```

Production-сборка находится в `dist`. `base: './'` поддерживает GitHub Pages в подпапке. Секреты и внешние AI API не требуются.

Дополнительный запуск через Docker:

```sh
docker compose up --build -d
```

Адрес: http://127.0.0.1:8088. Порт можно изменить переменной `PORT`. Остановка: `docker compose down`. Данные приложения остаются в браузере, а не в контейнере.

## Сценарий за минуту

1. Нажмите **Подобрать места**. После короткой сверки 350 мс откроется предпросмотр старых и новых адресов. Проверьте изменения и нажмите **Применить план** либо **Отмена**. До подтверждения назначения сохраняются; устаревший план применить нельзя. Это не запрос к AI.
2. Откройте Эдгара: исходные дома не выполняют все условия. **Создать идеальное место** заполняет параметры; выберите свободную локацию, сохраните и нажмите **Назначить и вернуться**. Совместимость и вместимость проверяются повторно, назначение закрепляется вручную. Отмена назначения сохраняет созданный дом.
3. Для Беллы с истёкшим сроком нажмите **+7 дней к сроку** или измените дедлайн в единой форме заявки. Новый дом сам по себе просрочку не исправляет.
4. Ручной выбор закрепляется замочком. Автоподбор сохраняет такой адрес и занимает его вместимость заранее. Конфликт требует отдельного подтверждения; он остаётся видимым в карточке и отчёте.
5. **Подтвердить переселение** фиксирует дату состоявшегося переезда. Выполненный вовремя дедлайн не становится просроченным позже. Завершённый адрес сохраняется при подборе, даже без ручного замочка. Для изменения сначала **Вернуть в план**.
6. Во вкладке **Отчёт** доступны все заявки, распределение статусов, свободная вместимость, JSON, текстовая сводка и печать. **AI Worklog** описывает инструменты, реальные запросы автора, ошибки AI и учёт времени.

Назначение — ещё план. В списке жильцов места могут присутствовать и запланированные переезды; завершение отмечено датой в карточке и отчёте.

## Темы и интерфейс

Выбор **Системная / Дневная / Ночная** находится под логотипом. По умолчанию используется системная тема, которая следует настройке устройства и её изменениям. Явный выбор сохраняется отдельно от сессии; прежние настройки дневной/ночной темы поддерживаются. Тема применяется до загрузки React. Экранный отчёт следует теме, печатный бланк остаётся светлым. Персонажи получили короткие реплики и раскрываемые истории; пользовательские заявки используют нейтральную реплику. Парит только большой портрет; при `prefers-reduced-motion` декоративное движение отключено. Срочность — дедлайн сегодня или завтра; просрочка отмечается отдельно.

На экране <=1150 CSS px выбранная заявка открывается вместо списка. **Все заявки** возвращает к списку с сохранением поиска. Переход к конкретному жильцу из места или отчёта сбрасывает мешающие фильтры и переводит фокус в карточку.

## Логика и ООП

`RelocationService` независим от React. Абстрактный `SuitabilityRule`, его реализации `ConditionsRule` и `AnxietyRule` позволяют подставлять правила через общий контракт. Сервис агрегирует правила и инкапсулирует их выполнение. UI — функциональные React-компоненты; наследование используется там, где есть предметный контракт.

Обязательные условия проверяются до оценки: чердак, отсутствие зеркал и людей, влажность >=65, свет <=30, шум <=30, предел тревожности. Дедлайн включителен, по локальной календарной дате браузера. Завершённый вовремя переезд освобождён от повторной проверки просрочки; текущие условия и вместимость продолжают проверяться.

```text
Комфорт = max(0, 100 - min(60, |желаемая температура - температура места| × 4)
                    - round(шум × тревожность / 25))
```

Температура — предпочтение. Min-Cost Max-Flow сначала максимизирует число назначений, затем общий комфорт. Обратные рёбра позволяют освободить единственный адрес требовательного призрака. При равенстве результат определяется порядком данных. Дедлайн и тревожность не дают дополнительного приоритета в оптимизации.

Закреплённые и завершённые назначения сохраняются первыми, их вместимость вычитается. Явно принятые ручные конфликты и переполнение не исправляются молча: нужно изменить решение или снять закрепление. Новые автоматические назначения не превышают оставшуюся вместимость.

## Управление и сохранение

- До 50 заявок; 10 иллюстрированных локаций, 5 исходных. Название связано с изображением; уже используемые изображения скрыты при добавлении.
- Заявки редактируются и удаляются с подтверждением. Места можно изменять и удалять: перед удалением видно число затронутых назначений; они снимаются вместе с замочками и признаком завершения. Действие можно отменить.
- Несохранённые изменения новой и существующей заявки, нового и существующего места защищены предупреждением при уходе и закрытии формы. Для даты используется один редактор. Метрики фильтруют все четыре категории заявок; отказ от ухода сохраняет текущий экран.
- Демосценарии требуют подтверждения. Подбор, изменения и удаления поддерживают отмену последнего действия в текущей вкладке браузера. История отмены не сохраняется после перезагрузки.
- Основная сессия: `quiet-address-v1`; тема: `quiet-address-theme`; игра: `quiet-address-game-v1`.
- **Сохранение и восстановление** выгружает полный JSON формата `quiet-address`, version 1. Импорт валидируется до изменения текущей работы и требует подтверждения замены. JSON-отчёт служит сводкой, а не резервной копией.
- Повреждённая сессия не перезаписывается: показывается временная демоверсия с заблокированным автосохранением. Можно скачать исходник или явно начать заново. При аварийном сбросе ErrorBoundary сначала сохраняет исходник в `quiet-address-recovery-v1`; если копия не записалась, сброс отменяется.
- Перед разрешённой заменой повреждённой записи или импортом поверх неё исходник также сохраняется в `quiet-address-recovery-v1`. При ошибке записи замена отменяется. Сохранённый исходник доступен для скачивания после перезагрузки.
- Перед каждой записью сессии и игры проверяется, не изменился ли исходник другой вкладкой; дополнительно используется событие `storage`. При конфликте запись приостанавливается: можно скачать локальную работу и явно загрузить свежую версию. Повреждённая свежая запись не применяется. Это защита optimistic compare-before-save: `localStorage` не даёт атомарной транзакции между вкладками. Серверных аккаунтов и совместного редактирования нет. Персональные данные, аналитика и заявки в сеть не отправляются.

## Пошаговая игра

Вкладка **Смена**: 3 смены, 6 персонажей, 3 дома по 2 места и 3 жетона улучшений. Время движется только после подтверждения прогноза конца смены. Следующие потребности известны заранее: тишина, темнота, сырость. Шумоизоляция, шторы и увлажнение стоят по одному жетону; бесплатного редактирования требований нет.

Советник подбирает адреса среди уже подходящих. Игрок решает, какое здание подготовить. Завершённые жильцы остаются и занимают места. Нерасселённая вовремя заявка даёт ноль очков и завершает свою историю. Итог — число переселённых и сумма их комфорта. Сохранение восстанавливается через проверенное воспроизведение действий; повреждённые данные требуют явного сброса.

Это небольшой детерминированный прототип, без реального таймера, случайных катастроф и внешнего AI во время игры. Его интерес и баланс ещё нужно проверить с пользователями.

Перед расходом жетона видно изменение параметра и выполняемое условие. Анализ реальных правил сравнивает пять стратегий и шесть планов полного расселения: лучший достижимый результат — 6/6 и 476 очков; финал распознаёт его. Запуск: `node scripts/analyze-game.mjs`. [Сценарий живого плейтеста](docs/playtest.md) подготовлен; реальный отзыв пока не получен.

## Изображения

10 AI-портретов и 10 AI-локаций с прозрачным фоном. Исходные PNG 1254×1254 сохранены; `ArtImage` отдаёт WebP 96/192/480/960 с PNG fallback. 80 производных занимают 4 751 288 байт против 36 334 821 байта исходников. Шесть начальных портретов 96px — 23 300 байт. Фактический выбранный размер зависит от экрана и DPR; это не замер всей сетевой загрузки.

`npm run check:assets` проверяет исходники, наличие производных, размеры, RIFF/WebP и прозрачность. Для повторной генерации отдельно нужен `sharp`: `node scripts/optimize-images.mjs` либо модуль через `SHARP_MODULE_PATH`. Обычная установка и сборка используют готовые файлы и `sharp` не требуют.

## Проверки

179 автотестов: исходные сценарии сохранены; автоподбор теперь требует явного применения предпросмотра. Проверяются три темы и изменение настройки ОС, защита черновиков и возврат фокуса, устаревание плана, межвкладочный конфликт сессии и игры, быстрое назначение с pin/undo, продление даты, восстановление, безопасный сброс, управление местами, отчёт/печать/Clipboard fallback, истории, игра и responsive-изображения. Два теста алгоритма включают 60 детерминированных сравнений с независимым полным перебором на маленьких графах.

Проверено 18 октября локально: текущая защита сессии и игры в двух настоящих вкладках Chrome, явная загрузка свежей версии; базовая компоновка пяти разделов в 45 сочетаниях темы и размера; предпросмотр Apply/Cancel/Escape и возврат фокуса, прогноз игры на 320 px. Подробные измерения и непокрытые состояния — [N8](docs/worklogs/N8.md). Ранее проверены копирование Markdown и прохождение 6/6 с восстановлением после перезагрузки. PDF через системный диалог не сохранялся: [N7](docs/worklogs/N7.md) содержит сценарии 0/6/50 заявок и ограничения приёмки.

Чеклист самостоятельной приёмки:

1. В чистой сессии подобрать адреса: увидеть сверку и предпросмотр. Отмена не меняет назначения; применение записывает план. Назначить вручную, повторить подбор и применить — адрес и замочек сохранены.
2. Выбрать срочную заявку, продлить на 7 дней: срок равен прежней дате +7 календарных дней; отмена возвращает прежнее значение.
3. Открыть редактирование: факты и назначения не дублируют редактируемую форму. Отмена сохраняет старые значения; уход с несохранёнными правками предупреждает.
4. Создать подходящее место Эдгару, назначить и вернуться; отмена назначения оставляет созданный дом. Отредактировать условия места: при несовместимости существующее назначение сохраняется с предупреждением.
5. Удалить занятое место с подтверждением: затронутые заявки остаются без назначения/замочка/завершения. Отмена последнего действия восстанавливает всё.
6. Нажать демосценарий и отменить — данные не меняются. Подтвердить и затем отменить последнее действие — возвращается вся предыдущая сессия.
7. Скачать резервную копию, импортировать её: все поля совпадают. Неизвестный формат/повреждённый файл оставляет текущие данные целыми.
8. В отчёте сверить суммы категорий и вместимость отдельно; скопировать сводку. Открыть печать, проверить страницы и сохранить PDF вручную.
9. В чистой сессии проверить системную тему; изменить тему ОС. Выбрать дневную/ночную, перезагрузить: явный выбор сохраняется и больше не следует ОС. Вернуть системную. Проверить фокус клавиатурой и отсутствие декоративного движения с reduced-motion.
10. На телефоне выбрать заявку и вернуться; из жильцов/отчёта перейти к заявке при активном поиске.
11. В игре улучшить замок для тишины, библиотеку для темноты, усадьбу для сырости; каждый раз использовать советника, посмотреть прогноз и подтвердить. Получить 6/6, перезагрузить и увидеть сохранённый финал.
12. Открыть две вкладки на одном origin. Изменить срок в первой: во второй запись остановлена, данные можно скачать или явно загрузить заново. Повторить с игровым улучшением; сессия и игра используют разные ключи.

## Финальная сверка MOX · 18 октября

В отчёте есть очередь «Требуют внимания»: ближайший срок, затем число нарушений текущего назначения и тревожность; одинаковые случаи упорядочены по ID. Показатели разделены: назначено адресов = переселено + ожидает переезда; без места считается отдельно, конфликты могут пересекать назначения. Эти данные присутствуют в интерфейсе, Markdown и JSON.

Общее время разработки — около 4 часов суммарно по оценке автора, включая чтение ТЗ, демо, продуктовую проверку, доработки и аудит. Это приблизительная оценка без полного тайм-трекинга, а не сумма длительности параллельных агентов.

Новый логотип состоит из знака и надписи; [исходники, размеры и промпты](docs/brand.md). Знак используется в навигации, отчёте и иконке вкладки. При финальной локальной проверке получены 4 назначенных адреса, 1 подтверждённый переезд, 3 ожидающих и 2 заявки без места; очередь начинается с просроченной Беллы. Логотип и отчёт проверены в обеих темах и на 320/390 CSS px.

## Публикация

GitHub Actions `Check` запускает проверки, `Deploy Pages` собирает и публикует main. В Settings → Pages должен быть выбран GitHub Actions. Успешная сборка не заменяет проверку публичной версии после публикации. Оценку выполнения тестового выставляет работодатель; гарантировать 5/5 нельзя.

## Полировка сохранения

Две карточки разделяют скачивание и восстановление. Выбор JSON-файла доступен с клавиатуры; после проверки видно имя файла, перед заменой требуется подтверждение. Повреждённый файл не меняет сессию, после отмены можно выбрать тот же файл повторно. Декоративные стрелки у кнопки подбора, жильцов и ссылки на исходники убраны.
