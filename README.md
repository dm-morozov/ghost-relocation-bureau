# Тихий адрес — Бюро переселения привидений

Панель оператора сказочного бюро: заявки, подбор адресов с объяснениями, ручные исключения, отчёт и AI Worklog в интерфейсе.

**Приложение:** https://dm-morozov.github.io/ghost-relocation-bureau/

**Репозиторий:** https://github.com/dm-morozov/ghost-relocation-bureau

## Запуск

Нужен Node.js 22.12+ (проверено на 24) и npm. Секреты, аккаунты, база и AI API не нужны.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://127.0.0.1:5173).

```sh
npm test           # автоматические проверки логики
npm run build     # строгая проверка TypeScript и сборка в dist/
npm run preview   # локальный просмотр production-сборки
```

Нажмите «Подобрать места». Из 6 исходных заявок 4 получат места, 2 останутся без адреса. Откройте Эдгара для разбора несовместимых условий и Беллу для просроченного дедлайна.

## Docker

```sh
docker compose up --build -d
```

Откройте http://127.0.0.1:8088. Порт можно изменить переменной окружения `PORT`. Сборка двухэтапная: Node собирает статику, nginx обслуживает её. Остановка: `docker compose down`. Контейнер — дополнительный способ запуска, для GitHub Pages он не нужен.

## Правила и алгоритм

Обязательные условия — жёсткие ограничения. Чердак, отсутствие людей/зеркал проверяются напрямую. Темнота означает свет ≤ 30, тишина — шум ≤ 30, сырость — влажность ≥ 65. Место ограничивает допустимую тревожность. Свет, шум и влажность — шкалы 0–100.

Дедлайн включителен, сравнивается с локальной календарной датой браузера (обновление каждые 30 секунд). Просроченные заявки автоматически не назначаются. Даты демоданных создаются относительно дня загрузки исходного сценария. Сохранённые даты со временем могут просрочиться.

Температура — предпочтение. Формула комфорта:

```text
max(0, 100 − min(60, |желаемая температура − температура места| × 4)
           − round(шум × тревожность / 25))
```

Пример: желаемые 10 °C, фактические 15 °C, шум 20, тревожность 5 → 100 − 20 − 4 = 76. Веса — открытая продуктовая гипотеза для сказочного домена.

Распределение — поток минимальной стоимости: сначала максимум расселённых, затем максимум суммарного комфорта. Обратные рёбра позволяют переназначить гибкую заявку ради заявки с единственным подходящим адресом. Новые автоматические назначения не превышают доступную вместимость; вручную закреплённое переполнение требует решения оператора. При равенстве используется порядок данных. Дедлайн и тревожность сортируют проблемные заявки в отчёте, но не дают приоритет при распределении.

Ручной выбор показывает нарушения до применения. Конфликтное назначение возможно только через отдельное «Всё равно назначить». В переполненном адресе все жильцы отмечаются как требующие внимания: система не решает за оператора, кто должен переехать. Ручной выбор автоматически закрепляется замочком. Автоподбор сохраняет закреплённые назначения и резервирует их вместимость. Конфликтные закрепления остаются с предупреждениями; при переполнении алгоритм не подселяет новых жильцов. Снять замочек можно в блоке текущего решения. Старые сессии без флага закрепления загружаются без замочков: происхождение старых назначений неизвестно.

## Архитектура и ООП

- `src/domain.ts`: модели и независимый от React `RelocationService`.
- `SuitabilityRule`: абстракция правила; `ConditionsRule` и `AnxietyRule` наследуют её и полиморфно реализуют `check`.
- Сервис агрегирует правила через конструктор; закрытое поле `rules` инкапсулирует проверку. Новое правило можно подставить без изменения алгоритма.
- `src/data.ts`: 6 демозаявок и 5 мест.
- `src/storage.ts`: валидация восстановленной сессии.
- `src/App.tsx`: интерфейс и состояние; `src/Worklog.tsx`: открытый журнал AI.

React-компоненты функциональные. Наследование не применяется к UI ради демонстрации ООП. Тестирование алгоритма не требует браузера и сети.

## Хранение и ограничения

До 50 заявок; каталог содержит 10 уникальных локаций (5 исходных и 5 резервных). Старые сессии с дубликатами сохраняются. Во вкладке «Места» нажмите «+ Новое место», заполните параметры и выберите изображение. Новый адрес сразу доступен для ручного выбора; повторный подбор учитывает его автоматически. При создании заявки доступны 10 AI-портретов. Данные хранятся только в localStorage текущего браузера. Старые сессии без справочника мест мигрируют автоматически. Сетевых запросов с заявками, аналитики и контактов нет. Два оператора не разделяют сессию. Кнопки сценариев заменяют заявки и назначения, сохраняя добавленные места. JSON-отчёт скачивается локально.

Повреждённая сессия не ломает запуск: показывается ошибка и загружаются демоданные. При недоступности хранилища интерфейс предупреждает о потере изменений после закрытия. ErrorBoundary перехватывает ошибки рендера. Синхронизация вкладок и серверный аудит не входят в эту версию.

## Проверка перед сдачей

33 автотеста: сохранение закреплённого адреса и вместимости, конфликтные закрепления, снятие замочка, валидация сохранённых закреплений, редактирование и отмена, удаление последней заявки; исходные проверки алгоритма и хранения, миграция справочника, сохранение нового места, недопустимые параметры места, создание подходящего адреса для Эдгара с восстановлением сессии, выбор портрета, предзаполнение идеального адреса и очистка шаблона, переход из жильца в заявку, нулевые значения initialData и пороги цвета шкалы 44/45/74/75.

## UI/UX: от заявки к новому адресу

Актуальная форма выбирает **локацию и изображение вместе**. Название закреплено за картинкой, его нельзя отредактировать; описание и параметры доступны для изменения. Пять резервных локаций — «Оранжерея туманов», «Часовая башня», «Лесная усадьба», «Забытая обсерватория», «Водяная мельница» — не добавляются автоматически. В обычной форме и при создании идеального адреса доступны только ещё не использованные изображения. После сохранения локация исчезает из выбора, в том числе после перезагрузки. Если весь каталог занят, форма объясняет это и не предлагает создать дубликат. Старые названия и назначения не переписываются.

Исправление кнопки: блок действий формы отделён от `.scenario-buttons`, который перекрывал фон primary и делал белый текст нечитаемым. Новая кнопка имеет собственный тёмно-зелёный фон. На этом этапе проходят 26 тестов, сборка и проверка 20 PNG; браузерная визуальная проверка не выполнена из-за отключённого управления браузером Work. Для ручной проверки: Эдгар → создать идеальное место → выбрать картинку с названием → изменить описание → «Добавить место» → повторно открыть форму и убедиться, что сохранённая картинка исчезла.

В карточке заявки без назначения доступно «🪄 Создать идеальное место». Кнопка открывает вкладку «Места» и форму с подобранными параметрами. Проверьте поля → «Добавить место» → вернитесь в заявки → «Подобрать места». Для Эдгара шаблон даёт комфорт 95/100 и выполняет его условия. Название «идеальное» означает соблюдение особых условий: формула всё ещё учитывает шум. Просроченный дедлайн остаётся отдельным ограничением, о чём сообщает карточка.

В текущем решении и кандидате показываются шкала комфорта, отклонение температуры, нагрузка от шума и чипы проверок. Зелёная шкала начинается с 75, янтарная — с 45, красная — ниже 45. Высокий комфорт не отменяет обязательные ограничения. Статусы «Назначено», «Без места» и «Конфликт» различаются цветом, текстом и боковой полосой строки. В карточках мест жильцы открывают соответствующие заявки; пустой адрес показывает «Пока никто не заселен».

UI/UX-обновление проверено локально в браузере на компьютере и при фактических 320/390 CSS px: предзаполнение, создание адреса Эдгара, подбор, переход из жильца и ручное назначение с нарушениями. ## Публикация

Workflow `Check` проверяет push/PR. `Deploy Pages` публикует main. При первой настройке в Settings → Pages выберите Source: GitHub Actions. Относительный `base` поддерживает подпуть репозитория. Публичная ссылка считается готовой после успешного deployment и браузерной проверки.

## AI Worklog

Отдельная вкладка **AI Worklog**: инструменты, учтённое время (около 20 минут на момент записи первого цикла), распределение работы, суть запросов, решения автора, ошибки AI и улучшения. Код написан AI по запросу автора; ручные правки автора не выдумываются. Дальнейшие изменения и авторское ревью нужно добавить к времени и журналу перед сдачей. Токены не считались: полная статистика недоступна.

## Управление заявкой

В карточке: «Редактировать заявку» открывает имя, портрет, тревожность, температуру, дедлайн и условия. Изменения сохраняют адрес и замочек; совместимость пересчитывается сразу. «Отмена» не меняет данные. «Удалить заявку» требует подтверждения с именем, затем снимает назначение и освобождает место. Удаление необратимо.

Проверка обновления: ручной адрес → подбор → перезагрузка сохраняют замочек; снятие замочка разрешает переназначение; добавление сырости в условия жильца сухого замка показывает конфликт; отмена редактирования и удаления сохраняет заявку; удаление последней заявки очищает назначения и закрепления. DOM-тесты автоматизированы. Визуальная проверка этого обновления в браузере недоступна: Local browser use отключён в Work settings.
